# 遗留问题、排错和后续路线

## 尚未解决或未充分验证

| 问题 | 当前程度 | 后续最小动作 |
| --- | --- | --- |
| 非公开稳定奖励 API | 当前可用，未来可能变更 | 更新前后只读核验字段和状态；有正式签到 API 时优先评估迁移 |
| 单机来源 | macOS 13 Intel 真机验证；公开版新增安装工具只有隔离测试 | 找独立新机器验收每日流程；Apple Silicon 单独验收，不能承诺全平台 |
| 加密实现依赖客户端内部 native provider | 标准 sym-v1 已验证；未知方案停止 | 新版只读确认格式，用合成测试复现；不关闭加密或导出密钥 |
| 真实登录过期后的整段恢复 | 错误分支有离线测试；完整自然过期恢复尚未验证 | 本人重新登录后观察真实只读查询和下一次 scheduled |
| 通知可见性 | 曾确认测试点击能打开客户端；修复后的测试系统接受已验证 | 每台机器本人确认横幅与点击；更新签名后重新检查权限 |
| 无运行时无法提醒 | 关机、睡眠、任务被卸载、Python 路径消失可能无法发通知 | 偶尔本机查 status；未来考虑独立健康检查，需要用户另行授权 |
| 长期稳定和不同账户类型 | 有多个自然日样本，曾出现加密升级故障 | 持续按日观察，收集脱敏状态码；企业域/接口不同则停止复核 |
| 免费旅行配置变化 | 指纹变化停住；缺费用字段不能自动证明免费 | 本人核对界面和规则，再重新预览并授权地点 |
| 精准时间 | 北京时间机器已见 06:30 实际触发；休眠/其他时区会延迟 | 保持唤醒、确认时区；不以开盖作为保证 |
| 过去漏领 | 能确认哪些日子没有自动成功 | 不提供补登、追补或伪造完成记录 |

## 按状态码处理

- `LOGIN_REQUIRED` / `LOGIN_REJECTED`：本人在 WorkBuddy 完成登录，再只读查询。仅打开应用不保证凭证续期。
- `ENCRYPTED_LOGIN_UNSUPPORTED` / `LOGIN_DECRYPT_FAILED` / `LOGIN_HELPER_UNAVAILABLE`：核对客户端版本、两个运行文件和安装位置；交维护者检查兼容。不要把密钥/令牌贴在 issue，也不要关闭加密。
- `NETWORK_UNAVAILABLE`：临时错误可等待下一轮；持续超过一小时会尝试提醒。只读检查网络，不通过重启 VPN、改 DNS/代理试错。
- `ACCOUNT_CHANGED_REVIEW_REQUIRED`：停住；确认本人是否切换账号。保留旧状态，另行规划账号迁移，不直接清空账号字段。
- `PREVIOUS_REQUEST_UNVERIFIED` / `GIFT_PREVIOUS_RESULT_UNKNOWN`：保存证据，查服务端和客户端；未知结果不重发、不删 pending。
- `TRAVEL_CONFIG_REVIEW_REQUIRED` / `TRAVEL_LOCATION_REVIEW_REQUIRED`：每日积分可能已成功，旅行停止；本人核实免费规则后才更新指纹。
- `RESPONSE_FORMAT_CHANGED` / `BUSINESS_REJECTED`：停止猜测；用脱敏合成响应覆盖测试，不能只放宽校验继续领奖。
- `HELPER_MISSING` / `NOT_AUTHORIZED` / `NO_RECEIPT`：这是通知通道问题，先查 app、系统授权与时间对应回执。不能把通知错误当作奖励一定失败，也不能把 QUEUED 当用户已看到。

## 路线与优先级

1. 先收集独立新机器的安装、跨日、锁屏和通知验收，完善兼容矩阵。
2. 自然出现真实凭证过期时，完成“提醒 → 本人重新登录 → 查询恢复 → scheduled 恢复”的证据链。
3. 改进安装错误细分和回滚验收；当前回滚已隔离测试，尚未在独立机器人为诱发真实系统注册失败。
4. 若有官方公开签到 API，评估通过正式授权接入，降低内部实现依赖。
5. 独立健康检查、跨平台、多账号与远程服务器运行均是新范围，不在 v0.1.0 承诺里；尤其不能将本机凭证上传到云端来解决休眠。

建议问题报告：操作系统/芯片/Python/WorkBuddy 版本、发生日期和时区、具体状态码、是否已手领、最后一个成功日期。仅提交手工筛选后的信息，不上传原始登录文件、状态或整份日志。
