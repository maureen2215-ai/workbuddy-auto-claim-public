## 离线验证方式

发布前运行 Python 奖励/登录/通知测试、Node 合成加密测试，以及新增安装/配置/管理工具的隔离测试。它们只使用临时目录、假的网络/系统返回值与合成 token，不能代表真实到账或系统弹窗已可见。`ci/offline-tests.yml` 提供可选 GitHub Actions 模板，首次发布未启用；模板也只做离线检查，不使用真人账号或 GitHub Secrets 领奖。

发布检查包括：源码/文档链接、敏感内容扫描、仓库文件白名单、全新单提交历史、生成 app 被忽略、公开仓库访问与匿名源码下载。新的精确测试数和发布版本记于 CHANGELOG。

## 成功标准

- `DAILY_CLAIM_VERIFIED`：脚本发出领取后服务端状态确认；结合本人客户端到账核对。
- `DAILY_ALREADY_VERIFIED`：服务端显示此前已领，不能归为脚本新增积分。
- `TASK_CLAIM_VERIFIED`：列表回查 claimed；旅行礼物需确定奖励回执与后续状态。
- `scheduled`、时间和 `screen_state=LOCKED`：证明当轮系统自然触发和锁屏事实，离线测试不能替代。
- `QUEUED`：系统接受通知；本人反馈看到并点击成功才证明可见交互。
- “已部署”：源码与运行副本核对一致，任务入口正确；Git push 或测试通过不能单独证明。
